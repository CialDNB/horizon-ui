### Task 12a: Table (+ Pagination)

Same standards as Tasks 10a-11c (task-10a-brief.md "Requirements for EACH component", porting-checklist, ALL ledger conventions/rulings). Table is the most-used composite after Typography/Button/Chip (42 runtime files, 46 runtime imports, 29 type-only imports in customer360) and needs the most design. Sources read-only under /Users/simonmor/dnb/x-core/src/components/{Table,Pagination,PaginationV2} (and its types: `Column`, `ColumnDataType`, `TableCellData`, `Order`, `DateCell`, `TableHeaderColumn`, cells: study `ls` for sub-components and the Table.types file customer360 imports: `@cialdnb/x-core/components/Table/Table.types`, 26 files); read how customer360 uses it (grep `<Table`, `columns`, `rows`, sorting (`orderBy`, `onSort`), pagination (`rowsPerPage`, `page`), selection, loading/empty states, custom cell renderers, sticky headers, row click, expandable rows, footers, `Order` type usage). Decide the API by evidence: a data-driven `Table` (columns + rows, matching x-core's contract closely enough to migrate mechanically) PLUS composable primitives (`TableRoot`, `TableHeader`, `TableBody`, `TableRow`, `TableHead`, `TableCell`, `TableCaption`) for custom layouts (shadcn-style); the data-driven component is built on the primitives.
Requirements:
- Semantics: real `<table>` markup (caption, `scope` on headers, `aria-sort` on sortable headers with a real button inside the header, row/column headers); sorting with keyboard and announced (status region or aria-sort changes), loading (aria-busy + skeleton rows/Spinner), empty state (role=status text), error state; row click/selection (checkbox column with Select-all and indeterminate, `aria-selected`), expandable rows only if x-core has them.
- Responsive Standard (the plan mandates): at mobile Table switches to a stacked card list OR a horizontally scrollable container with a visible scroll affordance (decide per customer360 table shapes: wide data tables scroll with sticky first column; short key/value tables stack): provide both via a `responsive` prop with a documented default; no horizontal page overflow at 320px; sticky header optional; 44px interactive targets (sort buttons, row actions, checkboxes) at mobile; per-breakpoint column visibility (`hideBelow: 'tablet' | 'laptop'` on a column) with the hidden columns reachable (row details) at mobile.
- Pagination (x-core `PaginationV2` latest; plus v1 uses map): page buttons with `aria-current="page"`, prev/next, rows-per-page select (use our Select), range text ("1-10 of 120"), collapses to prev/next + page indicator at mobile; keyboard; RTL arrows mirrored (logical); disabled edges; `nav` landmark with `aria-label`.
- Visuals per Horizon DS tokens (no Figma: apply Impeccable principles): density (compact/comfortable), zebra optional, hover row, selected row, borders `border` token, header text style, numeric columns right-aligned (`text-end`) with tabular numbers, truncation with title/tooltip, forced colors (borders/selected row visible), reduced motion.
- Coexistence: Bootstrap reboot/full bootstrap/`?host=customer360` set `table { border-collapse: collapse }`, `th { text-align: inherit }`, `caption { padding; color: #6c757d; text-align: left; caption-side: bottom }`, `.table` classes (unprefixed: never use); measure Table, Pagination in both builds and both orders; `?mui=v2` irrelevant except inside dialogs: add a Table inside a Horizon Dialog and a Drawer scenario (scrolling under scroll lock for a tall table: the scroll container must scroll).
- Performance: 500-row table render time test with a threshold; mention virtualization as future (no dependency).
- Props from x-core that .jsx callers pass: resolveOption + omitLegacyProps drop-and-warn; migration notes for `Column`, `Order`, `ColumnDataType`, `TableCellData` types (keep names where reasonable so type imports migrate: export compatible type aliases and list them in the map: 26 files import `Table.types`).
Per component: file layout, cva/cn, forwardRef + displayName, DnbBase, TSDoc, stories (variants x sizes/states, long text, RTL, brands side-by-side, Responsive with ResponsiveSpec), viewport tests with RED mutations at four viewports, contrast pairs for all brands (text 4.5:1; borders, selected row, focus ring 3:1), announce-once a11y, jsdom behaviour tests, a11y test:'error', exports + API snapshot, map rows (regenerate via `npm run usage-map`), dependency justifications (no new heavy deps), coexistence checks.
