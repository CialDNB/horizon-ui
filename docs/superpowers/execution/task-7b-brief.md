### Task 7b: Unlayered CSS build for legacy hosts (plan amendment, controller ruling)

Problem (measured in Task 7): customer360 ships UNLAYERED Bootstrap 4.4.1 reboot. Unlayered CSS beats any `@layer` CSS regardless of specificity, so horizon's layered `dist/styles.css` loses to element rules like `button { border-radius: 0; font-size: 1rem; line-height: 1.5; ... }` and the focus outline. Measured overrides on the Horizon Button (all 6 variants): border-radius 20px->0, font-size 14->16px, line-height 20->24px, focus outline 2px solid -> 5px auto.

Decision: ship two builds from the same pipeline (scripts/build-styles.ts):
- `dist/styles.css`: unchanged, layered (`@layer horizon`), for modern hosts where consumer unlayered CSS should override horizon.
- NEW `dist/styles.unlayered.css`: same rules, prefix-only (`hz:`), NO `@layer horizon` wrap, so class selectors (specificity 0,1,0+) beat Bootstrap's element selectors. For legacy hosts like customer360.
- package.json `exports`: add `./styles.unlayered.css`.

Requirements:
1. Generalize `buildStylesCss` (or add a sibling function) with an option `{ layered: boolean }`; unlayered output must still satisfy: no global preflight, no top-level selector outside `.hz-root` or `.hz\:` utilities, no `:root`/`:host`/`html`/`*` declarations of custom properties, `--tw-*` renamed `--hz-tw-*`, type sizes in px, prefix on all utilities; it must contain no `@layer` at-rule at all (Tailwind's internal `@layer theme/base/components/utilities` must be flattened away, preserving cascade order of rules: theme vars, base (.hz-root reset), components, utilities; verify the flattened order keeps utilities after base and variants (hover, focus-visible, inactive, tablet:/laptop:/desktop: media) after their base utility rules, exactly as Tailwind sorted them). `@property` registrations stay as today. The reduced-motion rule stays.
2. Vite lib build and vitest globalSetup emit both files; package `exports` updated; tests in src/__tests__/styles.test.ts extended (name them clearly, e.g. `'unlayered build contains no @layer'`, `'unlayered build has the same rule set as the layered build modulo the layer wrapper'` (compare normalized rule lists), `'unlayered build keeps cascade order: base before utilities, breakpoints after base utilities'`, `'unlayered build still has no preflight or global selectors'`). RED first.
3. Coexistence harness: add a mode that loads `styles.unlayered.css` instead of `styles.css` (e.g. query `?build=unlayered`). Update the "known limit" Bootstrap-reboot test group: for the UNLAYERED build, re-measure the same 6 Button variants with the unlayered Bootstrap 4.4.1 reboot loaded (both load orders: reboot before horizon CSS and horizon CSS before reboot) and assert that border-radius (20px), font-size (14px), line-height (20px) and focus outline (2px solid) are PRESERVED; keep the layered-build group asserting the documented override (that is the truth for the layered build). If some property is still overridden in the unlayered build (equal specificity + later reboot, or a pseudo-class rule like `button:focus` with higher specificity than the utility), find out exactly which and why, fix Button's classes in a way that keeps the Quality Bar (e.g. proper `focus-visible` variant specificity), or, if it can't be fixed without a design change, document it precisely in the ADR and report it. The plain-element leakage probes (button, h1, a, input, table, p, ul outside .hz-root) must also pass for the unlayered build with and without reboot.
4. Docs: ADR 0001 (new section: the two builds, when to use which, measured results for both, the order guidance for unlayered: load horizon CSS after legacy CSS, how consumer overrides work for the unlayered build: specificity/order, `hz:`-prefixed classes cannot collide by name), docs/architecture/03-packaging-and-distribution.md (exports list, CSS delivery), docs/architecture/05-migration-and-coexistence.md (customer360 uses the unlayered build; remove/adjust the "consumer must wrap legacy CSS in @layer legacy" requirement to be an option, not required), README consumer wiring snippet. Also update docs/superpowers/plans/2026-11-01-horizon-ui-foundation.md: insert this Task 7b (summarised) after Task 7 and amend Global Constraints "all output in @layer horizon" to "layered build in @layer horizon; unlayered build for legacy hosts".
5. Do not change Button's visual design. Do not break existing tests; update only what the ruling changes.
