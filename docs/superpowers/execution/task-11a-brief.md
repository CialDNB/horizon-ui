Components and key requirements:
1. Label (Radix Label or native `label`): required indicator, disabled styling, `htmlFor`; never relies on Bootstrap `label` rules (margin/display set explicitly).
2. Input: native `input` with `type` variants, sizes (md default 44px tall at mobile, 16px font at mobile to prevent iOS zoom; per breakpoint spec), states (hover, focus-visible ring, disabled, readOnly, invalid), start/end adornment slots (icons, buttons: adornment buttons need 44px targets or inline hit areas), clearable? (only if x-core has it), `aria-invalid`, `aria-describedby`; password visibility toggle only if x-core TextField used it (check). Number inputs: spin buttons hidden or styled consistently.
3. Textarea: auto-resize optional, `resize` rules explicit, same states.
4. FormField: composes Label + control + description + error message: wires `htmlFor`/`id`, `aria-describedby`, `aria-invalid`, `aria-required`; error text `role="alert"` only when it appears (announce once), description/ error contrast 4.5:1; layout stacks; works with Input, Textarea, Select, Checkbox, RadioGroup, Switch (a context-based `useFormField` is fine). Integrates with react-hook-form via plain props/`Controller` (do NOT add react-hook-form as a dependency; show an example in a story if it is a devDependency-free pattern; check what customer360 uses: grep react-hook-form/formik).
5. Checkbox (Radix Checkbox): checked/unchecked/indeterminate, label slot, 44px target at mobile via a hit area that does not overlap neighbours (reuse the hit-area learnings from Chip: separate aria-hidden layers or padding), focus ring, RTL, error state.
6. RadioGroup (Radix RadioGroup): arrow-key navigation, orientation, labels, disabled items, 44px targets, error state, roving focus; RTL arrow-key direction.
7. Switch (Radix Switch): role=switch, label, 44px target, RTL thumb direction logical, reduced motion, disabled.
8. Select: choose the implementation by evidence: Radix Select (custom listbox; best a11y/shadcn standard; portal content must use `usePortalContainer()` and render only when non-null) is the default; at mobile it must adapt (bottom sheet or full-width popover with 44px options: spec in Responsive story); search/typeahead; grouped options; disabled options; empty state; long option truncation; `value`/`onValueChange`/`placeholder`; native `<select>` fallback? (document the decision). Because overlays (Dialog, Popover, Tooltip) arrive in Task 11b, Select owns its own Radix portal now; follow the Portal rules in `src/provider/portal-context.ts` TSDoc (render Portal only when the container is non-null; outside provider falls back with a warn once).
