This runs `scripts/usage-report.ts` on customer360/client (x-core 2.2.30; the x-core checkout defaults to the sibling `x-core` directory, override with `--x-core`) so that names imported from the `components` barrel (types, hooks, enums) are attributed to their owning component folder, then rewrites the region between the markers. The hand-written columns (batch, horizon-ui name, API differences) live in `scripts/usage-map-curation.ts`; edit them there. For the raw report run `npm run usage-report -- <client-dir> --x-core <x-core-dir> [--json]`.

An import count is one imported binding (a named import, default import, namespace import, re-export or dynamic `import()`), so `import { Card, Chip } from '@cialdnb/x-core/components'` counts once for Card and once for Chip. **Runtime** and **type-only** imports are counted separately: a type-only import is `import type`, `import { type X }`, `export type`, or a name that x-core exports only as a type (`ChipProps`, `TableCellData`). Ranking uses runtime files (distinct files with a runtime import). Deep paths (`components/Table/Table.types`, `components/Dialog/useDialog`) count for the owning component. JSDoc `import("...")` type references in comments (2 in customer360: Drawer and AppBarActions types) are not counted.

Statuses: `todo`, `in-progress`, `done`, `partial` (ported, but some call sites use a feature that is not, see Blocked migrations), `superseded` (lower version of a family, never ported), `no-equivalent`, `skip` (not ported unless requested). Rows marked `unused-in-customer360` have no direct imports in the app. **Direct imports undercount composites**: `LayoutV2` renders AppBarV2, DrawerV2, AppBarActionsV2, HelpDropdown, NotificationsDropdownV2, ProductsDropdownV2 and UserPopover, so those are `todo` with a note rather than `skip`.

## Forms infrastructure: FormField (no direct x-core import)

`FormField` composes `Label` + one control + description + error and wires `htmlFor`/`id`, `aria-describedby` (description, then error), `aria-invalid` (when `error` is set, or `invalid`), `aria-required` (not native `required`: no browser bubbles) and `disabled` through a context that Input, Textarea, Select, Checkbox, Switch and RadioGroup read (RadioGroup is named by `aria-labelledby`). A control's own `id` (customer360 TextField call sites often pass one) is published back to the FormField, so the label's `htmlFor` follows the real id; without one the FormField `id` (or a generated one) is used. Checkbox/Switch with their own `label` are named by it alone: the FormField label then renders as a caption (not a second `<label>`). The error is mounted only while present, with `role="alert"` and an icon: announced once when it appears, not on re-renders. It replaces the `label`/`helperText`/`error` props of x-core TextField, TextInput, TextArea, SelectV2 and RadioGroup (`errorText`) and MUI FormControl/FormHelperText. Works with react-hook-form (`register` spreads onto Input/Textarea; `Controller` for Select/Checkbox/Switch/RadioGroup) and Formik without depending on either (customer360 uses both: react-hook-form 113 files, Formik 74). Dropped with a dev warning: `helperText`, `errorText`, `fullWidth`, `margin`, `sx`, `variant`, `color`, `focused`, `hiddenLabel`, `isLabelContainer`, `info`. Description and error are `<p>` with explicit margins (Bootstrap `p { margin-bottom: 1rem }` measured: no effect in `styles.unlayered.css`).

## Combobox (from `Autocomplete`, `CountryAutoComplete`; multi-select and search call sites of `SelectV2`/`Select`)

**Implementation decision: hand-rolled ARIA 1.2 editable combobox on Radix Popover; cmdk rejected.** Measured (esbuild, minified, React external): cmdk 1.1.1 alone 11.9 KB / 4.7 KB gzip with its Radix deps external, 52 KB / 17.9 KB gzip with them. A pill button (`aria-haspopup="dialog"`, `aria-expanded`; 44px at mobile, x-core's 32px with a fine pointer) with a selected-count bubble and an optional `totalCount` bubble (both `aria-hidden`; the counts are read from visually hidden text, or appended to a caller's `aria-label`), opening a Popover panel named by the label (`role="dialog"`, focus moves in and returns, Escape and outside press close) at `--z-popover`. `multiple`: Checkbox list (`role="group"` named by the label), committed **once when the panel closes**, as x-core without `applyButtonText`; with `applyLabel` changes are staged and committed by Apply (disabled until something changed), Reset (`resetLabel`) clears and closes, closing discards. `single`: RadioGroup, picking commits and closes (x-core `single`/`clean`). `searchable` adds an Input search; loading and "no options" are `role="status"` messages (x-core showed skeleton rows). `toggle` (x-core `disableMenu`) is a pressed/unpressed pill without a panel.
