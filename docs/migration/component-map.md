# Component map (x-core -> horizon-ui)

The tables below the `usage:start` marker are generated; do not edit them by hand. Regenerate with:

```
npm run usage-map -- /Users/simonmor/dnb/customer360/client
```

This runs `scripts/usage-report.ts` on customer360/client (x-core 2.2.30; the x-core checkout defaults to the sibling `x-core` directory, override with `--x-core`) so that names imported from the `components` barrel (types, hooks, enums) are attributed to their owning component folder, then rewrites the region between the markers. The hand-written columns (batch, horizon-ui name, API differences) live in `scripts/usage-map-curation.ts`; edit them there. For the raw report run `npm run usage-report -- <client-dir> --x-core <x-core-dir> [--json]`.

An import count is one imported binding (a named import, default import, namespace import, re-export or dynamic `import()`), so `import { Card, Chip } from '@cialdnb/x-core/components'` counts once for Card and once for Chip. **Runtime** and **type-only** imports are counted separately: a type-only import is `import type`, `import { type X }`, `export type`, or a name that x-core exports only as a type (`ChipProps`, `TableCellData`). Ranking uses runtime files (distinct files with a runtime import). Deep paths (`components/Table/Table.types`, `components/Dialog/useDialog`) count for the owning component. JSDoc `import("...")` type references in comments (2 in customer360: Drawer and AppBarActions types) are not counted.

Statuses: `todo`, `in-progress`, `done`, `superseded` (lower version of a family, never ported), `no-equivalent`, `skip` (not ported unless requested). Rows marked `unused-in-customer360` have no direct imports in the app. **Direct imports undercount composites**: `LayoutV2` renders AppBarV2, DrawerV2, AppBarActionsV2, HelpDropdown, NotificationsDropdownV2, ProductsDropdownV2 and UserPopover, so those are `todo` with a note rather than `skip`.

### Porting order recommendation

1. Finish Batch 1 around real usage: Typography (291 files), Chip (57 files), Spinner from CircularProgress (49 files), Alert, Badge, Avatar, Separator, IconButton, Progress. Button is done.
2. Batch 2 inputs next because every form screen needs them together: Input (TextField 43 files, TextInput 10 files) with FormField, Select, Checkbox, RadioGroup, Switch, Autocomplete (Combobox), then overlays Dialog, Tooltip, Popover, Drawer, Toast, then SplitButton and Filter (need DropdownMenu/Popover).
3. Batch 3 starts with Table (42 files, the most-used composite) and Card (+ InsightsCard, LevelCard), then Tabs, Accordion, Timeline, Pagination, then NavigationDrawer + AppBar + Layout as one unit (customer360 consumes it through `LayoutV2`).
4. Batch 4 only on request: the live items are the charts (AreaChart, StackedBarChart, VerticalBarChart) and the pickers (DatePicker, DateRangePicker); most chart, legend and map variants have no imports.
5. Skip everything marked `skip` and `unused-in-customer360` unless a consumer asks (il-acl-client uses Breadcrumbs, PasswordField, InputCompany, FilterInput, DualDataCard, SearchBar and Timeline, which customer360 does not).
