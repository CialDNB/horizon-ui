# Component map (x-core -> horizon-ui)

The tables below the `usage:start` marker are generated; do not edit them by hand. Regenerate with:

```
npm run usage-map -- /Users/simonmor/dnb/customer360/client
```

This runs `scripts/usage-report.ts` on customer360/client (x-core 2.2.30; the x-core checkout defaults to the sibling `x-core` directory, override with `--x-core`) so that names imported from the `components` barrel (types, hooks, enums) are attributed to their owning component folder, then rewrites the region between the markers. The hand-written columns (batch, horizon-ui name, API differences) live in `scripts/usage-map-curation.ts`; edit them there. For the raw report run `npm run usage-report -- <client-dir> --x-core <x-core-dir> [--json]`.

An import count is one imported binding (a named import, default import, namespace import, re-export or dynamic `import()`), so `import { Card, Chip } from '@cialdnb/x-core/components'` counts once for Card and once for Chip. **Runtime** and **type-only** imports are counted separately: a type-only import is `import type`, `import { type X }`, `export type`, or a name that x-core exports only as a type (`ChipProps`, `TableCellData`). Ranking uses runtime files (distinct files with a runtime import). Deep paths (`components/Table/Table.types`, `components/Dialog/useDialog`) count for the owning component. JSDoc `import("...")` type references in comments (2 in customer360: Drawer and AppBarActions types) are not counted.

Statuses: `todo`, `in-progress`, `done`, `superseded` (lower version of a family, never ported), `no-equivalent`, `skip` (not ported unless requested). Rows marked `unused-in-customer360` have no direct imports in the app. **Direct imports undercount composites**: `LayoutV2` renders AppBarV2, DrawerV2, AppBarActionsV2, HelpDropdown, NotificationsDropdownV2, ProductsDropdownV2 and UserPopover, so those are `todo` with a note rather than `skip`.

### Porting order recommendation

1. Finish Batch 1 around real usage: Typography (291 files), Chip (57 files), Spinner from CircularProgress (49 files), Alert, Badge, Avatar, Separator, IconButton, Progress. Button is done.
2. Batch 2 inputs next because every form screen needs them together: Input (TextField 43 files, TextInput 10 files) with FormField, Select, Checkbox, RadioGroup, Switch, Autocomplete (Combobox), then overlays Dialog, Tooltip, Popover, Drawer, Toast, then SplitButton and Filter (need DropdownMenu/Popover).
3. Batch 3 starts with Table (42 files, the most-used composite) and Card (+ InsightsCard, LevelCard), then Tabs, Accordion, Timeline, Pagination, then NavigationDrawer + AppBar + Layout as one unit (customer360 consumes it through `LayoutV2`).
4. Batch 4 only on request: the live items are the charts (AreaChart, StackedBarChart, VerticalBarChart) and the pickers (DatePicker, DateRangePicker); most chart, legend and map variants have no imports.
5. Skip everything marked `skip` and `unused-in-customer360` unless a consumer asks (il-acl-client uses Breadcrumbs, PasswordField, InputCompany, FilterInput, DualDataCard, SearchBar and Timeline, which customer360 does not).

Visual deviations from ButtonV2 (no Figma link was available; decisions in the Task 6 report):

- Heights at tablet and up: sm 24 -> 32px, md 36px (same), lg 42 -> 44px (4px grid). Mobile and touch pointers: 44/44/48px minimum target.
- Type: sm 10 -> 12px, md 12 -> 14px (the Horizon `button` token), lg 14 -> 16px; semibold; no 1.25px letter-spacing.
- Radius 20px in both directions (ButtonV2 used 16px in RTL).
- No elevation (ButtonV2 forced `box-shadow: none` on the component anyway).
- Secondary hover fills with `primary` (as ButtonV2 outlined); tertiary hover underlines (as ButtonV2 text with `showTextUnderLine`). The end-icon bounce animation is not ported (decorative motion).

## Forms infrastructure: FormField (no direct x-core import)

`FormField` composes `Label` + one control + description + error and wires `htmlFor`/`id`, `aria-describedby` (description, then error), `aria-invalid` (when `error` is set, or `invalid`), `aria-required` (not native `required`: no browser bubbles) and `disabled` through a context that Input, Textarea, Select, Checkbox, Switch and RadioGroup read (RadioGroup is named by `aria-labelledby`). The error is mounted only while present, with `role="alert"` and an icon: announced once when it appears, not on re-renders. It replaces the `label`/`helperText`/`error` props of x-core TextField, TextInput, TextArea, SelectV2 and RadioGroup (`errorText`) and MUI FormControl/FormHelperText. Works with react-hook-form (`register` spreads onto Input/Textarea; `Controller` for Select/Checkbox/Switch/RadioGroup) and Formik without depending on either (customer360 uses both: react-hook-form 113 files, Formik 74). Dropped with a dev warning: `helperText`, `errorText`, `fullWidth`, `margin`, `sx`, `variant`, `color`, `focused`, `hiddenLabel`, `isLabelContainer`, `info`. Description and error are `<p>` with explicit margins (Bootstrap `p { margin-bottom: 1rem }` measured: no effect in `styles.unlayered.css`).

## Textarea (from `TextArea`)

Native `<textarea>` with the Input look (inset `control-border` ring, primary hover, 2px focus ring, destructive invalid, muted disabled), padding 12px 16px, radius 20px, 4 rows. Text 16/20 at every breakpoint (multi-line text needs the leading; x-core used 14px). The custom x-core drag handle becomes the native vertical `resize` handle; `resize="none"` hides it; `autoResize` (+ `maxRows`) grows with the content instantly. `label`/`helperText`/`error` move to `FormField`; `minRows` is `rows`; `characterLimit` is native `maxLength` (no visible counter yet). Unchanged by Bootstrap and customer360 host CSS in `styles.unlayered.css`; the layered build takes Bootstrap's `line-height: inherit` and `resize: vertical` (measured).

## Icons

x-core `icons` is `export * from '@phosphor-icons/react'` plus 14 deprecated legacy aliases. horizon-ui re-exports Phosphor unchanged from the subpath: `import { CheckIcon } from '@cialdnb/horizon-ui/icons'` replaces x-core's `icons` namespace usage (there is no root `icons` namespace); legacy aliases are not carried over, use the `*Icon` names. Under `dir="rtl"`, pass `mirrored` on directional icons (`ArrowLeftIcon`, `ArrowRightIcon`, `CaretLeftIcon`, `CaretRightIcon`, `ArrowBendUpLeftIcon`).

## Illustrations

x-core renders each SVG through `<img src width={50} height={50}>`. horizon-ui renders inline `<svg>` components (generated by `scripts/port-illustrations.ts` from the verbatim SVGs in `src/illustrations/assets/`): `aria-hidden` unless `title`/`aria-label`, `size` sets width and height, intrinsic size is the artwork's own (not 50px), ids unique per instance. Props change from `ImgHTMLAttributes` to `SVGProps` (`alt` becomes `title`/`aria-label`, `src` is gone).
